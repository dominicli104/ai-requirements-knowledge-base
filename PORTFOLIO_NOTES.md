# Portfolio Notes

## Proposed use-case walkthrough

1. Analyst receives a proposed requirement document.
2. Analyst extracts requirements with stable IDs and section references.
3. Analyst reviews wording and scope before baselining.
4. Analyst searches exact IDs or business concepts and examines source evidence.
5. Analyst records gaps, duplicate/contradictory items and version changes.
6. Analyst traces requirements to validation scenarios and makes status visible.

## Demonstrated vs. not implemented

**Implemented in this public demo:** searchable predefined fictional register; filters; detail display; sample source reference; no-evidence state.

**Illustrated by documentation, not implemented:** live ChatGPT Projects document retrieval; OCR of documents; semantic embedding / vector store; automatic traceability sync; connection to actual client systems; production authentication and permissions.

## Interview-ready explanation

> I designed an evidence-first requirements lookup workflow: preserve source statements and IDs, make status and version explicit, and return no answer when there is no source. I used ChatGPT to accelerate the prototype and documentation, then defined deterministic test cases to validate the public demo.
